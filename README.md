# 矩形板材下料 · 断头切割排料（Panel Nesting）

面向小型手作工坊的矩形板材裁切排样 Web 应用。支持两种模式：

- **单订单排料**：输入原板长 / 宽、锯缝宽度以及各零件的长 / 宽 / 数量，系统按
  **固定输入顺序**、遵循**断头切割（guillotine cut）**规则逐板生成裁切方案，
  并以图示标出零件、余料与①②③……下刀次序。
- **多订单拼版**：每个订单填写**唯一订单号**与零件清单（不同订单可使用同名零件），
  多个订单拼在同一批原板上，按**订单输入顺序及其零件行输入顺序**依次断头切割，
  落位保留订单归属。输入每张原板材料价后，每张板的材料费按各订单在该板的
  **零件实际面积比例**分摊（换算成分后以最大余数法分配尾差，同余按订单输入顺序），
  结果按订单列出跨板零件的件号、所在板号与坐标，供分单取件。

- 前端：React 18 + Vite
- 后端：Node.js + Express（排料算法见 `server/src/cutting.js`）
- 部署：Docker / Docker Compose（镜像内完成依赖安装与前端构建，一键启动）

## 一条命令启动

```bash
docker compose up -d --build
```

该命令会自动完成：安装 npm 依赖 → 构建 React 静态资源 → 启动 Node 服务。

启动后访问：

> **http://localhost:8080**（Web 页面与 API 同端口）

停止服务：`docker compose down`

## 必要配置

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `PORT` | 宿主机暴露端口（在项目根目录 `.env` 中设置，可由 `.env.example` 复制） | `8080` |

然后访问 http://localhost:9090 。

## 本地开发（不使用 Docker）

要求 Node.js ≥ 18。根目录一条命令安装所有 workspace 依赖：

```bash
npm install
```

分别启动后端（8080）与前端开发服务器（5173，已配置 `/api` 代理）：

```bash
npm run dev:server    # 终端 1
npm run dev:client    # 终端 2
```

访问 http://localhost:5173 。

生产方式本地运行（先构建再由 Express 托管）：

```bash
npm run build
npm start             # http://localhost:8080
```

算法自检（单订单 + 多订单拼版与费用分摊）：

```bash
npm test
```

## 使用说明

### 单订单排料

1. 填写**原板长度、原板宽度、锯缝宽度**（单位统一即可，通常用 mm；锯缝可为 0）。
2. 在零件清单中填写每种零件的长度、宽度、数量；可添加 / 删除行，或点击「载入示例」。
3. 点击「生成裁切方案」。结果区显示：
   - **用板数**、零件总数、零件总面积、**锯缝损耗面积**、**余料总面积**、利用率；
   - 每张板的裁切图：米黄色为余料、彩色块为零件、灰色锯缝带上的虚线为刀刃，
     圆形数字徽章即**下刀次序**；
   - 每板的零件落位表（坐标、尺寸、是否旋转）与刀路表（方向、起终点、贯穿长度）。
4. 若零件旋转后仍大于原板，页面会明确报错，指出是哪一种零件尺寸超限。

### 多订单拼版

1. 填写**原板长度、原板宽度、锯缝宽度**与**每张原板材料价（元）**
   （非负、最多两位小数）。
2. 逐个添加订单：每单填写**唯一订单号**和零件清单（长 / 宽 / 数量）；
   不同订单允许使用**同名零件**。
3. 点击「生成拼版方案」。结果区显示：
   - 用板数、订单数、零件总数、**材料费合计**、余料总面积、总利用率；
   - **分单取件**：按订单列出全部零件（含跨板）的件号、所在板号、坐标、
     尺寸与是否旋转，以及该订单分摊的材料费；
   - **逐板裁切图**（按订单着色，刀序规则与单订单一致）、每板的
     **材料费分摊表**（订单 → 该板零件面积 → 分摊金额，合计恰为板价）与
     落位 / 刀路明细。

## 切割规则

- 零件**严格按用户输入顺序**排料（同种零件数量 N 即连续 N 件），不做大小重排；
  多订单时先排完一个订单的全部零件行，再排下一个订单，落位保留订单归属。
- 每件零件允许旋转 90°；余量相同时优先不旋转。
- 零件在所有已开板材中都放不下时才开启新板，尽量减少用板数。
- 每件零件落入某个当前可用矩形区域的左上角，需要两刀释放：
  - **竖切优先方案**：先竖切（贯穿该区域全高），再在左侧料块上横切；
  - **横切优先方案**：先横切（贯穿该区域全宽），再在上侧料块上竖切；
  - 自动选择锯缝损耗更小的方案，平局取竖切。
- 每一刀都**贯穿当前所在矩形区域**，锯缝宽度从余料一侧扣除并计入损耗；
  沿板边的修整切若余边不足一条完整锯缝，则按实际余边宽度落刀。
- 零件在某方向恰好占满区域时，该方向不再下刀。
- 余料面积 = 原板总面积 − 零件面积 − 锯缝损耗面积。

## 材料费分摊规则（多订单）

- 每张原板材料价（元，非负、最多两位小数）先换算成**分**。
- 每张板按各订单在该板的**零件实际面积比例**分摊该板材料费：
  先按精确份额向下取整到分，剩余尾差用**最大余数法**逐分补给余数最大的订单；
  **余数相同时按订单输入顺序**优先。
- 由此保证：每板各订单分摊额之和**恰好等于该板板价**；各订单跨板汇总之和
  **恰好等于全部用板的总板价**（材料费合计 = 用板数 × 每张材料价）。

## API

### `POST /api/cut`（单订单排料）

```json
{
  "boardWidth": 2440,
  "boardHeight": 1220,
  "kerf": 3,
  "parts": [
    { "name": "柜门", "width": 600, "height": 400, "quantity": 4 }
  ]
}
```

### `POST /api/cut-orders`（多订单拼版）

```json
{
  "boardWidth": 2440,
  "boardHeight": 1220,
  "kerf": 3,
  "boardPrice": 128.50,
  "orders": [
    {
      "orderId": "A001",
      "parts": [{ "name": "柜门", "width": 600, "height": 400, "quantity": 3 }]
    },
    {
      "orderId": "A002",
      "parts": [{ "name": "柜门", "width": 550, "height": 380, "quantity": 2 }]
    }
  ]
}
```

`boardPrice` 为每张原板材料价（元，非负、最多两位小数，缺省按 0 计）。
返回的 `result` 主要字段：

- `boards[]`：逐板方案，`placements[]` 带 `order`（订单归属）、`costShares[]`
  为该板材料费分摊（`order` / `partsArea` / `amountCents` / `amount`）；
- `orders[]`：分单取件清单，每单含 `items[]`（零件、件号、所在板号 `board`、
  坐标 `x,y`、尺寸、是否旋转）与分摊材料费 `costCents` / `cost`；
- `boardPriceCents`、`totalCostCents` / `totalCost`：单板价与材料费合计。

两个接口成功均返回 `{ "ok": true, "result": { ... } }`；零件无法放入原板或输入非法
（订单号重复 / 为空、板价为负或超过两位小数等）时返回 HTTP 400 与
`{ "ok": false, "error": "..." }`。
