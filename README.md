# 矩形板材下料 · 断头切割排料（Panel Nesting）

面向小型手作工坊的矩形板材裁切排样 Web 应用。输入原板长 / 宽、锯缝宽度以及各零件的
长 / 宽 / 数量，系统按**固定输入顺序**、遵循**断头切割（guillotine cut）**规则逐板生成
裁切方案，并以图示标出零件、余料与①②③……下刀次序。

- 前端：React 18 + Vite
- 后端：Node.js + Express（排料算法见 `server/src/cutting.js`）
- 部署：Docker / Docker Compose（镜像内完成依赖安装与前端构建，一键启动）

## 一条命令启动

```bash
docker compose up -d --build
```

该命令会自动完成：安装 npm 依赖 → 构建 React 静态资源 → 启动 Node 服务。

启动后访问：

> **http://localhost:8080**

停止服务：`docker compose down`

## 必要配置

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `PORT` | 宿主机暴露端口（在项目根目录 `.env` 中设置，可由 `.env.example` 复制） | `8080` |

容器内服务固定监听 8080 端口；如需改用 9090，可在 `.env` 中写 `PORT=9090`，
然后访问 http://localhost:9090 。

## 本地开发（不使用 Docker）

要求 Node.js ≥ 18。根目录一条命令安装所有 workspace 依赖：

```bash
npm install
```

分别启动后端（8080）与前端开发服务器（5173，已配置 `/api` 代理）：

```bash
npm run dev:server    # 终端 1
npm run dev:client    # 终端 2
```

访问 http://localhost:5173 。

生产方式本地运行（先构建再由 Express 托管）：

```bash
npm run build
npm start             # http://localhost:8080
```

## 使用说明

1. 填写**原板长度、原板宽度、锯缝宽度**（单位统一即可，通常用 mm；锯缝可为 0）。
2. 在零件清单中填写每种零件的长度、宽度、数量；可添加 / 删除行，或点击「载入示例」。
3. 点击「生成裁切方案」。结果区显示：
   - **用板数**、零件总数、零件总面积、**锯缝损耗面积**、**余料总面积**、利用率；
   - 每张板的裁切图：米黄色为余料、彩色块为零件、灰色锯缝带上的虚线为刀刃，
     圆形数字徽章即**下刀次序**；
   - 每板的零件落位表（坐标、尺寸、是否旋转）与刀路表（方向、起终点、贯穿长度）。
4. 若零件旋转后仍大于原板，页面会明确报错，指出是哪一种零件尺寸超限。

## 切割规则

- 零件**严格按用户输入顺序**排料（同种零件数量 N 即连续 N 件），不做大小重排。
- 每件零件允许旋转 90°；余量相同时优先不旋转。
- 零件在所有已开板材中都放不下时才开启新板，尽量减少用板数。
- 每件零件落入某个当前可用矩形区域的左上角，需要两刀释放：
  - **竖切优先方案**：先竖切（贯穿该区域全高），再在左侧料块上横切；
  - **横切优先方案**：先横切（贯穿该区域全宽），再在上侧料块上竖切；
  - 自动选择锯缝损耗更小的方案，平局取竖切。
- 每一刀都**贯穿当前所在矩形区域**，锯缝宽度从余料一侧扣除并计入损耗；
  沿板边的修整切若余边不足一条完整锯缝，则按实际余边宽度落刀。
- 零件在某方向恰好占满区域时，该方向不再下刀。
- 余料面积 = 原板总面积 − 零件面积 − 锯缝损耗面积。

## API

`POST /api/cut`

```json
{
  "boardWidth": 2440,
  "boardHeight": 1220,
  "kerf": 3,
  "parts": [
    { "name": "柜门", "width": 600, "height": 400, "quantity": 4 }
  ]
}
```

成功返回 `{ "ok": true, "result": { ... } }`；零件无法放入原板或输入非法时返回
HTTP 400 与 `{ "ok": false, "error": "..." }`。
